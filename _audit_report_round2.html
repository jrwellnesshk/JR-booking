一、本輪修復清單（問題 → 修法 → 證據）

P0已修+驗證病歷相片可無需登入下載

問題：/uploads 靜態閘門先於 /uploads/medical_records 認證 handler 註冊 → 相片被 express.static 直接放行，任何知道 URL 的人都能下載病人病歷相片（醫療隱私重大外洩）。

修法：server.js 將醫療檔案認證 handler（JWT → clinic_session cookie → 擁有權檢查）移到靜態閘門之前註冊；其他 uploads（頭像等）照舊公開。

證據：無認證 → 401（修復前 200）｜擁有者 JWT → 200｜擁有者 cookie（<img> 元素式）→ 200｜其他客戶 → 403｜員工 → 200

P1已修+驗證clinic_session cookie Secure 旗標誤設

問題：secure: NODE_ENV==='production' — production 環境以 http 服務時瀏覽器拒收 Secure cookie → 病歷相片 <img> 全部 401。

修法：routes/auth.js 按實際協議 req.secure || x-forwarded-proto==='https'（trust proxy 已開）。

證據：http 登入 → set-cookie 不含 Secure，cookie 正常下發。

P2已修+驗證DELETE /api/bookings/clear 空 body → 500

問題：無 payload 的 DELETE 令 const { bookingIds } = req.body 拋 TypeError → 500 + stack 噴 stderr。

修法：routes/bookings.js → req.body || {} 防禦。

證據：無 body → 400；空 JSON → 400；stderr 零 TypeError。

P2已修+驗證家庭連結後戶主 isHead 誤判

問題：account-links 升級雙方 family 但漏幫戶主補 family_head_id=自己 → /family-payment isHead=false，戶主被引導「接手供款」。

修法：routes/memberships.js 補一行鏡像寫入（與 H3 單一來源設計一致）。

證據：連結後 owner(head=44/44)、target(head=44) 均 tier=family；family-payment → isHead=true, canTakeOver=false；戶主代成員預約非初體驗 → 200。

取消已完成音頻功能取消（只保留相片・按業主要求）

後端：multer 只收 photos、fileFilter 只放行圖片、新病歷 audio_file_path=null、PUT 不再收新錄音、兩個音頻下載端點移除、AI 分析「錄音 +0.3」因素移除。

前端：index.html 播放器＋下載掣、js/app.js 映射＋下載函數、staff/admin.html 播放器＋麥克風圖標、「及錄音」提示、privacy.html 提及 — 全部移除。

證據：mp3 上傳 → 被拒；純相片 → 200 且 audio=null；音頻端點 → 404；病歷 history → 200。

資料：舊音頻記錄不動；上線後可選擇 UPDATE medical_records SET audio_file_path=NULL ... 清理。

二、Admin/HR 401 之謎 — 結案：harness artifact，產品零問題

根因（兩個，實錘）：① nav-click smoke 點到側欄登出掣 — admin.html 登出無 confirm 閘，一撳即 POST /api/auth/logout revoke jti → 之後所有 API 401；② hr.html 登出掣係純圖標掣（textContent 空、只有 :title），文字過濾攔唔到。

修法（harness 層）：_audit5_visual.cjs monkey-patch window.fetch，nav-smoke 期間封鎖 POST /api/auth/logout — 唔使理 UI 文字／圖標。

結果：admin/HR 8/8 全綠；全矩陣 32/32 格：0 水平溢出、0 真實錯誤、0 真實 4xx/5xx（8 場景 × zh-TW/en × desktop/mobile）。

副產品：admin 登出無二次確認（staff/doctor 有）。非 bug，屬 UX 取捨，建議上線前考慮加 confirm。
