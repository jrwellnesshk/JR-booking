## Scene 1.2｜四個方案，點解揀 EC2（3:00）

- **畫面**：[SCREENSHOT-02] 對比表（方案／月費／啱唔啱／原因）。
- **旁白**：
  「四個諗法。／
  第一，EC2——即係租一部虛擬機，自己裝 Docker。月費大約十到十八美金，控制晒，我哋揀呢個。／
  第二，Lightsail——AWS 自己嘅『懶人 VPS』，五到十美金固定價，畫面簡單好多。**如果你只想要最平最簡單，Lightsail 十蚊嗰檔其實好合理**，缺點係同 IAM、S3、CloudWatch 嘅整合冇咁完整。／
  第三，ECS Fargate——managed container。聽落先進，但 Fargate 嘅磁碟係臨時嘅，container 一停，我個 SQLite 檔案就冇咗。要用就一定要駁 EFS，成本高一大截。**所以唔好揀。**／
  第四，Lambda——更加唔啱，無狀態、無磁碟、有執行時間限制。／
  另外 RDS？我哋用 SQLite，完全唔需要，開咗每個月白白俾廿幾美金。／ALB？一部機唔使负载均衡，Caddy 已經做咗反向代理同 TLS。開 ALB 每個月又係廿幾美金。／

- **指令**：—
- **驗證**：觀眾講得出「點解唔用 Fargate」（因為 ephemeral disk）。
- **陷阱**：網上好多 tutorial 教你 ECS + RDS + ALB，嗰啲係為咗高可用、多實例；單機 SQLite 唔适用。
- **安全**：唔好為「睇落專業」而開多餘服務，每開一樣就多一個收費同攻擊面。

# 第 2 章｜AWS 開戶全流程（14:00）

## Scene 2.1｜開戶前準備（2:00）

- **畫面**：準備清單投影片：電郵、信用卡／扣賬卡、身分證明（可能需要）、手機收 SMS、公司資料（地址、電話）。
- **旁白**：
  「開戶前準備幾樣嘢：／一個**唔好同其他人共用**嘅電郵——我強烈建議開一個專用嘅，例如 `aws-admin@你公司域名`，或者用 Gmail 個 plus 地址。／因為呢個係 root 帳戶，一世都改唔到。／
  一張信用卡或者扣賬卡，AWS 會先扣一蚊港幣左右做驗證，之後會退返。／
  一部收到 SMS 嘅手機，做身分驗證用。／
  仲有你嘅公司或者個人地址，要填真實嘅，因為帳單資料要用。」
- **指令**：—
- **驗證**：—
- **陷阱**：唔好用會離職嘅員工私人電郵做 root；唔好用自己日常電郵（root 係釣魚攻擊嘅頭號目標）。
- **安全**：🔒 root 電郵 = 成個 AWS 帳戶嘅命根，獨立 + 開 MFA。

## Scene 2.2｜逐步開戶（8:00）

- **畫面**：[SCREENSHOT-03] 瀏覽器 <https://aws.amazon.com> → 「Create an AWS Account」，逐步錄：
  1. Root user email address → Verify email address → 輸入驗證碼
  2. Create password（≥ 8 位，含大小寫數字符號）
  3. Contact information：Account type 揀 **Business**（個人都可以揀 Personal，功能一樣）
  4. 地址、電話（電話要真實，會打嚟驗證）
  5. Billing information：卡號、到期日、賬單地址
  6. 身分驗證：輸入電話號碼 → 選 SMS / Voice → 輸入 CAPTCHA（聽住讀出嚟嗰段）→ 輸入 4 位驗證碼
  7. Support plan：揀 **Basic support – Free**（其餘要俾錢）
  8. 完成 → 「Go to the AWS Management Console」
- **旁白**：
  「去 aws.amazon.com，右上角『Create an AWS Account』。／
  第一步填電郵。呢個就係你嘅 **root user email**，一世改唔到，認真填。／跟住去郵箱攞驗證碼。／
  第二步設密碼。用密碼管理器整個長密碼，唔好重用任何其他網站嘅密碼。／
  第三步聯絡資料。個人用就揀 Personal，公司就揀 Business；分別只係賬單同稅務資料。／地址同電話要真實，因為之後真係會打嚟。／
  第四步信用卡。佢會先做一筆小額授權驗證，之後會退返，唔係收費。／
  第五步身分驗證。揀 SMS，輸入你嘅電話，打佢畀你嗰個驗證碼，跟住輸入驗證碼。／
  第六步支援計劃——**一定要揀 Basic，免費嗰個**。其餘兩個每個月收幾十到幾百美金，你而家唔需要。／
  之後就完成，等幾分鐘帳戶啟用，就可以登入。」
- **指令**：—
- **驗證**：見到 AWS Management Console 首頁，右上角見到 region 選單。
- **陷阱**：
  - 身分驗證 CAPTCHA 有時會聽唔清楚，可以揀「文字驗證」或者重聽。
  - 支援計劃揀錯要俾錢；事後可以降級（Billing → Manage support plan）。
  - 開完戶有時要等 10–20 分鐘先完全生效，唔好以為失敗。
- **安全**：🔒 呢個電郵同密碼就係 root。開完戶第一件事唔係開機，係落 MFA（第 3 章）。

## Scene 2.3｜Region 揀邊個（4:00）

- **畫面**：Console 右上角 region 選單，展示 `ap-southeast-1 (Singapore)` 同 `ap-east-1 (Hong Kong)`。
- **旁白**：
  「右上角呢度揀區域。／兩個選擇：／
  **新加坡 ap-southeast-1**——新帳戶預設開通，對香港延遲大概三十幾毫秒，服務種類最齊，價錢中等。我建議用呢個，穩陣。／
  **香港 ap-east-1**——離你最近，延遲最低，但**新帳戶要另外申請開通（opt-in）**，有時要等，而且部分實例類型冇得開，價錢通常貴少少。／

  **重要**：揀咗區就固定用嗰區。AWS 嘅資源係分區嘅，你喺新加坡開嘅機，去香港區係睇唔到嘅。」
- **指令**：—

- **安全**：只開你需要嘅區，減少管理面。

# 第 3 章｜開戶後 5 分鐘安全加固（**必做**）（10:00）

## Scene 3.1｜Root 開 MFA（3:00）

- **畫面**：[SCREENSHOT-04] 右上角帳戶名 → Security credentials → Multi-factor authentication (MFA) → Assign MFA device → Authenticator app → 掃 QR code（用手機 Google Authenticator / 1Password / Authy）→ 輸入兩組連續 MFA code。
- **旁白**：
  「登入之後，**唔好急住開機**。先做五分鐘安全設定，呢五分鐘可以幫你慳返幾萬蚊同無數麻煩。／
  第一件事：root 開 MFA。／右上角你個帳戶名，撳落去，Security credentials。／拉落去搵 Multi-factor authentication，Assign MFA device。／名隨便填，揀 Authenticator app。／
  佢會出一個 QR code，用手機嘅 Google Authenticator、1Password 或者 Authy 掃。／之後要輸入**連續兩組**六位數字——因為佢每三十秒換一次，所以你要等佢跳去下一組再打第二個。／
  完成之後，每次用 root 登入都要打多六位數字。／
  點解咁重要？因為 root 係唯一一個可以刪晒你所有資源、改賬單資料嘅身份。冇 MFA，一個密碼洩漏就全毀。」
- **指令**：—
- **驗證**：MFA 狀態變成 `Enabled / Active`；登出再登入一次，確認要打 MFA code。
- **陷阱**：兩組 code 要**連續**，唔可以打完第一組等一陣；失敗就等三十秒再做。
- **安全**：🔒 呢一步係全片最高優先級。

## Scene 3.2｜刪除 Root Access Key（2:00）

- **畫面**：Security credentials → Access keys 區 → 顯示 `No access keys`（如有則 Delete），並展示 `Your security credentials` 頁面頂部嘅警告。
- **旁白**：
  「第二件事：確認 root 冇 Access Key。／同一版 Security credentials，搵 Access keys 嗰一欄。／
  正常新帳戶係冇嘅，會寫住『No access keys』。如果你見到有，或者係以前自己開過，**即刻 Delete**。／
  點解？Access Key 係俾程式用嘅長期憑證，一旦洩漏，人哋可以開幾百部挖礦機，一個晚上燒你幾千美金。／
  root 根本唔應該有 Access Key。日後要用 CLI，我用 IAM 用戶或者 IAM Role，第 13 章會講。」
- **指令**：—
- **驗證**：Access keys 顯示「No access keys」。
- **陷阱**：有啲舊教學教你開 root access key 用 CLI——**唔好**。
- **安全**：🔒 root 只做人類登入 + MFA，唔做程式存取。

## Scene 3.3｜開 IAM 管理員用戶 + MFA（3:00）

- **畫面**：IAM Console → Users → Create user → 名 `admin-damian` → Attach policies directly → `AdministratorAccess` → Create → 入去 Security credentials → Assign MFA device → 記錄 login URL（Dashboard 嘅 `IAM users sign-in link`）。
- **旁白**：
  「第三件事：開一個 IAM 用戶做日常使用。／去 IAM，Users，Create user。／名例如 `admin-damian`。／唔好剔『提供 console 存取』先……不，我哋要開，因為要用 console 登入，所以剔『Provide user access to the AWS Management Console』。／
  權限方面，直接 Attach policies，揀 `AdministratorAccess`。／個人項目咁樣就得；如果係團隊，之後應該收窄做 custom policy。／
  開完，入去呢個 user，Security credentials，照樣開 MFA。／
  跟住記低 IAM 頁面頂部嗰條『IAM users sign-in link』，例如 `https://123456789012.signin.aws.amazon.com/console`。／
  由今日開始，用呢條 link 加 IAM 用戶登入，除咗極少數操作（改賬單資料、關帳戶）之外，都唔好用 root。」
- **指令**：—
- **驗證**：用 IAM sign-in link 登入成功，右上角顯示 `admin-damian @ 1234-5678-9012`。
- **陷阱**：右上角落顯示嘅係帳戶 ID，唔係用戶名；要認住用戶名係 `admin-damian`。
- **安全**：🔒 日後用 IAM；root 收埋。

## Scene 3.4｜Budget + Billing 告警（2:00）

- **畫面**：[SCREENSHOT-05] Console 搜尋 `Budgets` → Create budget → Zero-spend / Monthly cost budget → 門檻 US$10 → Alert threshold 80% 同 100% → 填電郵 → Create budget。再開 Billing preferences → 剔 `Receive CloudWatch billing alerts`。
- **旁白**：

- **驗證**：`cat ~/.ssh/aurora-aws.pub` 出一行以 `ssh-ed25519 AAAA...` 開頭、以 `aurora-aws` 結尾嘅字串。
- **陷阱**：
  - 權限太闊（`644` 私鑰）→ SSH 報 `UNPROTECTED PRIVATE KEY FILE`。

- **安全**：🔒 私鑰唔好擺 iCloud／AirDrop／GitHub；passphrase 用密碼管理器記。

## Scene 12.2｜設 SITE_DOMAIN 並重啟（3:00）

  之後等十幾秒，Caddy 就會去拎證書。／
  驗證：curl -I，睇吓有冇出 200 同 HSTS header。」
- **指令**（伺服器上）：
```bash

# 1) 加 SITE_DOMAIN

sed -i 's|email .*|email your-real@email.com|' Caddyfile

# 3) 重啟（唔使 rebuild）

# 4) 睇 Caddy 拎證書過程
docker compose logs -f caddy | grep -i "cert\|acme\|tls"
```
- **驗證**：
```bash

# strict-transport-security: max-age=31536000; includeSubDomains

# 第 13 章｜備份 + **還原演練**（12:00）

## Scene 13.1｜兩層備份策略（2:00）

- **畫面**：架構圖：EBS Snapshot（整機，每日）＋ SQLite 邏輯備份上 S3（每日，異地）。
- **旁白**：
  「備份要兩層。／第一層：EBS Snapshot——成個硬碟嘅快照，出事可以成部機還原，用 AWS 嘅 Data Lifecycle Manager 自動每日做，保留七日。／
  第二層：SQLite 邏輯備份——用 `sqlite3 .backup` 出一個一致嘅資料庫檔，gzip 之後放上 S3。／

## Scene 14.1｜CloudWatch 基本告警（4:00）

- **畫面**：CloudWatch → Alarms → Create alarm → 揀 EC2 metric `CPUUtilization` → 門檻 > 80% 持續 5 分鐘 → 設 SNS 通知（Create new topic + email）→ 命名；再做 `StatusCheckFailed` 告警。

  ⚠️ CloudWatch 基本監控**冇磁碟使用率**。要監控 disk，要裝 CloudWatch Agent 或者自己寫 cron metric。／最簡單：用 cron 每日 check 一次 disk，超過八成電郵通知。」

EOF

crontab -e
# 加：0 8 * * * /home/ubuntu/disk-check.sh
```
- **驗證**：CloudWatch → Alarms 見到 2 條 alarm，State = `OK`；電郵收到 SNS confirm 信並已確認。
- **陷阱**：SNS 訂閱未確認就收唔到通知。
