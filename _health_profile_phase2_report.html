一、需求（Phase 2）

Phase 1 已完成「客人自填 + 醫護唯讀搜尋」。Phase 2 追加：

  • 醫師／員工／管理員三個門戶都可以喺「客人檔案」直接編輯客人嘅長期病患、長期用藥、過往病歷。
  • 醫師儲存即視為專業確認，檔案顯示「醫師已確認 · 姓名 · 時間」。
  • 員工／管理員儲存只改內容、唔產生確認標記（確認權留俾醫師）。
  • 提供獨立「確認內容無誤」掣：只寫確認標記，唔改動任何內容。
  • 客人日後修改內容 → 舊確認標記自動作廢，需重新確認；內容不變再儲存則保留標記。

三、驗證結果

A. 後端 API（21 項，全 PASS）

  • migration 三欄已建立：verified_at, verified_by, updated_by
  • 醫師 PUT → 200 + verified=true，標記帶 role=doctor、醫師姓名、時間
  • 客人改內容 → 標記作廢；原內容再儲存 → 標記保留
  • 員工 PUT → role=staff；管理員 POST /verify → role=admin 且內容不變
  • 權限矩陣：客人 403 ×2、未登入 401 ×2、非 customer ID 404、非數字 ID 400、未填寫檔案 verify 404
  • 邊界：9000 字截斷至 5000；空 body → 200 唔 500；stderr 零 TypeError

四、排查紀錄（兩個假 FAIL）

客人端「健康檔案 section 未渲染」並非產品 bug。 同一瀏覽器先開過 admin.html，localStorage 殘留 adminUser；js/app.js:4109 嘅既有邏輯會將佢跳去 admin.html， 所以 index.html 渲染出嘅係管理員介面。驗證腳本已改為開客人端前先清除其他門戶嘅 localStorage key，模擬乾淨瀏覽器。
第二個假 FAIL 係等待不足：客人端 Vue mount + 導航需要更長時間，已改為輪詢式等待（最多 ~9 秒）。

五、已知行為（非缺陷，維持原狀）

  • 管理員／員工喺同一瀏覽器開過後台後再開客人頁，會被導去後台 —— 屬既有設計，本輪冇改動。
  • 只有「醫師」儲存會直接產生確認標記；員工／管理員儲存只改內容。如日後要畀員工確認權，只需改 routes/healthProfiles.js 嘅 isDoctor 判斷。
  • 本輪全程用 VACUUM INTO 快照 + 獨立埠（4763），無觸摸 live database.db；live dev server（:4000）未重啟。
